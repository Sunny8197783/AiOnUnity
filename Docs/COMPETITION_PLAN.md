# 경보 이전: 경진대회 업그레이드 실행 계획

작성 2026-11-20. 근거 문서: 기능 제안서(https://claude.ai/artifact/1ULm1KqqeRc5gMY6ypypkZ).
범위: 제안서의 필수·권장·여유 항목 전부와, 그래픽 사실화(실사형 인물 모델 포함).

## 원칙

1. **비폭력, 공식 출처.** 화면에 적이나 폭력이 나오지 않습니다. 안전 문장은 출처 있는 facts만 씁니다. 새 사실은 `Data/Source/facts-ext.json`에 두어 원작 대조 테스트(facts 95개)와 섞지 않습니다.
2. **원작과 갈라지는 지점은 기록합니다.** 챕터, 체크포인트, facts를 바꾸면 해당 parity 테스트를 고치고, 이 문서의 "갈라짐 기록"에 이유를 남깁니다.
3. **단계마다 끝냅니다.** 각 단계는 구현 → 리뷰 2명(정확성·플레이 품질) → 수정 → 테스트 전부 통과 → 실제 장면 확인 → 커밋·푸시 순서로 닫고 다음으로 넘어갑니다.
4. **확인되지 않은 수치는 쓰지 않습니다.** "2분 교대", 1337, 111·113, 경량칸막이 세부 수치, 사이렌 패턴, 민방위 훈련 횟수, 소화기 방사 시간은 제안서 사실 확인 표의 권장 문구를 따릅니다.

- 2장 대피소: 명부를 쓰고 자리에 앉은 뒤(`DDay.ShelteredMark` 다음, 서연 파트 전) 옆 돗자리 할아버지가 쓰러집니다(`Story/CprScene.cs`, 화면 `UI/Screens/CprScreen.cs` "cpr", 규칙 `Game/CprLogic.cs`, 문구 `Game/CprText.cs`). 반응 확인 → 이름으로 지목해 119·AED(“누가 좀”과 직접 신고하러 뛰어가기는 다음으로 넘어가지 않음) → 호흡 확인 10초(15초가 지나면 저절로 넘어감) → 110 BPM 압박(`AudioSettings.dspTime` 기준, 누르는 시간 = 깊이, 다음 박자 0.14초 전까지 떼야 이완) → 100초에 AED(전원 → 패드 → 분석 중 손 떼기, 닿으면 분석을 다시 → 충격 → 바로 재개; 12초 동안 아무도 누르지 않으면 자원봉사자가 대신) → 150초 이후(충격 뒤 20초 이상) 구급대 인계 → 돌아보기(실제 품질 곡선과 게이지 곡선). 결말은 항상 구급대 인계이고 사망·부상 묘사는 없습니다. 교사용 모드의 공습경보 장면은 이 장면 전에서 끝납니다.
- 숨은 피로: 자기 압박 60초부터 60초에 걸쳐 판정 창 30% 축소, 필요한 누름 시간 최대 1.9배, 최대 깊이 0.6(약 3cm). 최대 깊이 제한만으로도 혼자 누르면 90초(`CprLogic.SoloShallowAt`)부터 약 4cm(0.8) 아래로 내려가므로, 이완이 허락하는 만큼 길게 눌러도 AED(100초) 전에 얕아집니다(리뷰 반영: 예전 수치로는 세게 누르는 사람에게 111초 전에는 드러나지 않았음). 게이지는 '느끼는 깊이'로 계산하고, 느끼는 피로는 자기 압박 186초(Ochoa 1998 중앙값)부터라서 게임 길이 안에서는 게이지에 깊이 저하가 드러나지 않습니다(박자·이완 실수는 바로 보임). 쉬면 초당 2초씩 회복. 교대는 이름으로 지목한 이웃(파란 점퍼)만 움직이고 2초 손 바꿈, 30초 뒤 다시 넘겨받습니다. 이 수치들은 게임 수치이며 사실 문장이 아닙니다(화면에는 cpr_fatigue, cpr_fatigue_why 문장만 출처와 함께).
- 접근성: 판정 넓게(창 1.8배, 박자는 그대로), 원버튼(박자만 판정, 깊이는 피로에 따라 자동, 1초 길게 누르면 교대 요청), 게임패드 진동 메트로놈, 청각 모드는 소리 대신 화면 테두리 박자 강조, 저시력 모드는 단계 문장을 읽어 줌(HostSettings.Speak), 움직임 줄이기는 손 떨림·고리 크기를 줄임. 체험 모드가 있으면 넓은 판정이 기본, 이동·휠체어·지체 모드는 원버튼이 기본(첫 화면에서 바꿀 수 있음).

Fates 낯선 사람 줄 1개. 학습 리포트에 축 `care`(응급 처치)와 행 5개(cprPoint, cprBreath, cprRhythm, cprSwap, cprAed) — 리포트 테스트 `EveryRowPointsAtARealFact`는 이제 facts.json+facts-ext.json 병합본으로 확인합니다.

- 리뷰 반영(11-21, 2차):
  - AED 단계는 압박 버튼의 다음 박자가 아닙니다: 단계가 바뀐 뒤 1초(`StepLock`) 동안, 그리고 0.8초(`StepPause`) 이상 손을 멈춘 뒤가 아니면 Space는 단계를 넘기지 않고 "잠깐 손을 멈추고 AED 안내를 보세요"를 띄웁니다. 화면의 AED 버튼·Enter·패드 RB는 1초 잠금만 따릅니다. 분석 중에는 누르고 있는 것도 닿음입니다(0.6초 이상 눌린 채면 한 번). 분석 재시작은 3번까지, 그 뒤에는 자원봉사자가 "손 떼세요!" 하고 분석을 끝까지 진행합니다(닿음은 계속 셈). 분석·충격 중에는 박자 점·테두리 깜빡임·진동을 멈추고 테두리를 고정된 주황으로 둡니다. AED 소리는 전원을 켤 때 "power", 분석 "analyze", 충전 "charge", 충격 "shock"이며 따로 둔 세 번째 AudioSource로 냅니다(메트로놈 예약을 끊지 않음).
  - 판정 행 `cprRhythm`(사실 `cpr_depth_rate`): 직접 누른 압박 20회 이상, 자기 박자의 75% 이상을 누르고 실제 품질 평균 0.5 이상이면 ✓. 압박이 20회 미만이면 "압박 깊이가 유지됐습니다"라고 하지 않습니다. 교대는 압박 20초 이후여야 "지치기 전에"로 인정합니다. 얕아진 구간이 없던 판(교대한 경우 등)에도 "혼자 계속 눌렀다면 1분 30초쯤부터 얕아졌겠지만 게이지는 그대로 높게 보였을 것"이라는 줄을 보여 줍니다(게임 수치이며 옆에 `cpr_fatigue_why`).
  - 호흡 확인: 본문에 "가슴이 오르내리지 않는다. 몇 초에 한 번 '컥' 하고 헐떡일 뿐이다"를 먼저 보여 주고, 2D 그림의 가슴이 몇 초마다 한 번 헐떡입니다(움직임 줄이기면 멈춤). 새 사실 `cpr_gasp`("호흡이 없거나 헐떡이는 등 정상적으로 숨 쉬지 않으면 심장정지를 의심하고 가슴압박을 시작합니다", 정책브리핑 카드뉴스, 11-21 다시 확인)를 호흡 단계에 `cpr_breath`와 함께 보이고, 헐떡임을 호흡으로 본 판의 cprBreath 행이 이 사실을 가리킵니다. 그 카드뉴스 출판사는 페이지의 출처 줄대로 "대한민국 정책브리핑(질병관리청·대한심폐소생협회)"로 고쳤습니다. 출처에 없던 "흔들어 일으키지 않습니다"는 뺐습니다. 사실은 18개·출처 9개입니다.
  - 저시력: 한 단계를 한 문장으로(무엇이 일어났는지, 제목, 상황, 번호 붙은 선택지) 읽고, 호흡 10초는 읽기가 끝난 뒤(글자당 약 0.13초, 3~30초)부터 셉니다(`CprLogic.DelayBreath`). 10초는 목표로 그대로 둡니다.
  - 게임패드: 매 프레임 uGUI 선택을 비우고(DocsScreen 규칙), 압박 화면이 아닌 페이지는 십자키·스틱 위아래로 고르고 A로 누릅니다. 압박 화면은 A 누르기, Y 교대 요청/다시 이어 누르기, X "누가 좀", RB AED 버튼이며 패드가 있으면 조작 줄에 함께 적습니다.
  - 그림: 손·박자 고리·위치 표시를 가슴 한가운데(복장뼈 아래쪽 절반, 깃에서 몸통 1/3쯤)로 올리고, 두 팔을 한쪽(왼쪽 아래)에서 나란히 곧게 뻗은 모양으로 바꿨습니다. 문구: 할아버지는 "뒤로 스르르 쓰러졌다"(누운 모습과 맞춤), 첫 페이지는 같은 문장을 되풀이하지 않습니다. 덱 `cpr_relay` 문장에서 "지치기 전에"를 뺐습니다(디브리핑의 늦은 교대 판정과 어긋나지 않게).
  - 2장 마무리 카드: 도구 이름 "심폐소생술"과 결과 "이웃과 교대하며 구급대에 넘겼습니다"/"혼자 압박을 이어 구급대에 넘겼습니다"(플레이하지 않은 판은 줄 없음; docs 카드의 "skipped"와 섞이지 않게 따로 둠).
  - 장면 바로가기로 시작한 판에서만 충격 뒤 "구급대 도착까지 건너뛰기" 버튼이 나옵니다(심사용 짧은 체험). 이야기에서는 늘 끝까지 갑니다.
  - 서연 파트의 시각: CPR 장면이 서연 파트 앞이라 12분(`CprScene.Minutes`)이 먼저 흐르고, 정민의 문자(보낸 시각 = 앉은 시각 + 2분)와 그에 이어지는 시각(C 경사로 열림 = 보낸 뒤 3분, 서연이 받는 시각)이 12분 늦어집니다(기본 플레이스루: 보냄 20:23→20:35, 받음 20:27→20:39). 의도한 결과로 둡니다: 정민은 구급대가 올 때까지 할아버지 곁에 있었고, 그동안 문자를 보내지 못했습니다. 메모의 '본 시각'과 '보낸 시각' 사이가 길어지는 것도 정보가 낡는다는 이 장면의 교훈과 맞습니다. `AfterAlert`의 경계경보·해제 시각은 `Math.Max`로 정하므로 앞뒤가 뒤집히지 않습니다. 원작 대조 테스트는 CPR 없이 돌려 원작 시각을 그대로 확인합니다.
- 장면 바로가기 "대피소 심폐소생술" 활성화: 재개 키 `DDay.CprResume`("cpr", 준비된 저장만 가짐), `Resources/Demo/cpr.json`(기본 플레이스루에서 CPR 화면이 열리는 순간, 20:21). 다른 준비 저장은 다시 만들지 않았습니다.
- 사람 애니메이션: 눕는 클립이 없어(`down`은 엎드리는 자세) `UnityPerson`에 `lie`를 더했습니다(idle 클립 + 모델을 뒤로 눕힘). 할아버지는 회색 머리인 crowd2 모델입니다(화면 그림과 같음).

**2단계 "불나면 살펴서 대피" (11-21)**
- 3장 복도 화재(`Endure.CorridorFire`) 첫머리, 집 안에서 화면 "lookfirst"(`UI/Screens/LookFirstScreen.cs`, 규칙 `Game/LookFirstLogic.cs`, 이야기 `Story/LookFirstScene.cs`)를 엽니다. 살피기(손등으로 문손잡이 · 문틈 · 복도 소리(청각 모드는 현관문 진동) · 집 안 · 관리사무소 방송(청각 모드는 인터폰 화면) · 재난문자) → 불은 어디? → 어떻게(계단으로 나가기 / 집 안에서 버티기 / 베란다 경량칸막이 / 엘리베이터) → (문틈 막기 | 칸막이) → 119 신고 카드 → 돌아보기. 판단 페이지는 `DecisionMoment`입니다.
- 살피는 데 시간이 듭니다(단서마다 2~8초, 게임 수치). 304호 어르신이 두드리지 않았으면 12초(`LookFirstLogic.GrowAfter`)를 넘겨 살필 때 불이 상자 더미로 번지고(`size: large`), 화면을 닫은 뒤 3D 복도의 불도 큰 불로 시작합니다.
- 판정은 소방청 지침 표(`LookFirstLogic.Judge`, 시나리오와 무관): 우리 집 불이면 나갈 수 있으면 계단, 못 나가면 대피공간·경량칸막이, 버티기는 마지막; 다른 집 불이면 연기가 없을 때 집 안 대기(`fire_stay`), 연기가 들어오고 복도·계단이 비었으면 대피, 복도·계단에 연기가 찼으면 구조 요청(문 닫고 젖은 수건, `fire_seal`)이나 경량칸막이. 엘리베이터는 언제나 303호 서연이 말리는 교정(다시 고름). 3장 상황은 "다른 집(복도) 불, 문틈으로 연기"이므로 작은 불이면 '나가기'가, 커졌으면 '버티기'·'칸막이'가 ✓이고 나머지는 "다시 생각해 볼 점"으로 이유를 보여 주며 그대로 진행합니다(처벌 없음).
- '나가기'는 원래 3D 장면(소화기, `Escape.SmokeEscape`) 그대로입니다. 이 경우 1층에 내려온 뒤 119 신고 카드(`mode: report`, 거는 곳 1층)를 하고, 박 소장 대사가 "신고 잘했어요"로 바뀝니다(살피기를 하지 않은 판은 원작 대사). '버티기'와 '칸막이'는 복도 장면 없이 화면 안에서 끝나고, 25분(게임 시간) 뒤 소방대원이 불을 끕니다(`fire_waited`). 칸막이를 넘은 판은 D+3 서연의 첫 대사가 바뀝니다.
- 칸막이는 모델에 이미 있던 베란다 서쪽 끝 '경량칸막이' 판(301호 쪽)입니다. 1장 집 안 대비·장비 점검 중에 새 지점 `homePartition`("베란다 끝 벽 (경량칸막이)")에서 이사 상자를 치울 수 있습니다(10분, know `partitionCleared`, 이벤트 `partition_cleared`, 레벨 상태 `partition` = boxes 기본 / clear / broken, 상자는 `InteriorDressing`이 그림). 치우지 않았으면 3장에서 상자 3개를 먼저 옮깁니다. 칸막이는 5번 누르거나 길게 누르며, "길게 누르기 대신 켜 두기"(이동·휠체어·보호자 모드 기본)로 한 번 눌러 계속 밀 수 있습니다. 휠체어 모드의 '나가기' 문구는 "도움을 청해 이웃과 함께 계단으로"입니다.
- 장면에 지점을 넣는 메뉴: `AiOn → Levels → Add Partition Point (Apartment)` (apartment-level.json을 다시 읽어 `ApartmentLayout.asset`에 반영하고 Apartment.unity에 InteractionPoint 하나를 넣음, 여러 번 실행해도 같음).
- 3D 엘리베이터: 연기 탈출(`Escape`)과 살핀 뒤의 복도 장면에서 엘리베이터를 누르면 303호 서연이 말리는 대사와 `fire_lift`(원작은 사실 토스트만). `Escape.NeighbourStops`, `Endure.LookPart`가 시험 시임이고, 원작 대조 테스트(`EndureTests`)는 둘 다 끄고 돌립니다.
- facts-ext.json에 4개, 출처 1개 추가(11-21 페이지 확인): `fire_other_smoke`, `fire_report`(정책브리핑 소방청 "화재 대피요령 완벽 가이드" — 다른 집 불·연기 유입 시 판단, 119 신고 요령), `fire_partition`, `fire_partition_clear`(인천중부소방서 2021.2.8 "'생명의 문' 아파트 경량칸막이 중요성 홍보", incheon.go.kr). 경량칸막이 두께 등 수치는 쓰지 않았습니다. 사실 22개·출처 10개입니다. "동·호수"는 출처 문구("화재 발생 장소를 정확히")를 카드 문장으로 옮긴 것이며 사실 문장에는 넣지 않았습니다. 재난문자 단서의 "이 불은 문자로 오지 않는다"는 이야기 서술이지 안내 문장이 아닙니다.
- 기록: 이벤트 `lookfirst`(요약), `fire_report`(1층 신고), `fire_waited`, `partition_cleared`, `elevator_tried{fire:true}`(3D 교정). 학습 리포트 화재 축에 행 4개(`lookWhere`, `lookAct`, `lookLift`, `report119`), 사전 대비 축에 `partition`. 준비 회고(`Ripples`)에 prep `partition`("경량칸막이 앞 비우기", 원인 `partition_cleared`)를 원작 표 뒤에 덧붙였습니다(`Ripples.PortAdded`) — `RipplesTests`·`DebriefTests`의 원작 표 대조는 원작 키만 비교하도록 고쳤습니다. 받아 둔 물로 수건을 적시면 `tub` 보답, 1장에 치운 칸막이로 피하면 `partition` 보답이 뜹니다.
- 장면 바로가기 "살펴서 대피" 활성화: 재개 키 `Endure.LookResume`("look", 준비된 저장만 가짐), `Resources/Demo/look.json`(기본 플레이스루의 "fire" 체크포인트 상태를 "look" 키로). "복도 화재"와 같은 저녁에서 시작하며 둘 다 살피기 화면을 거칩니다. `SceneSelectTests`의 "준비 중 칸" 기대값을 빈 목록으로, 타이틀 시험의 시작 불가 예시를 없는 id로 바꿨습니다.
- 리뷰 반영 (11-21, 2차):
  - '나가기'를 고르면 3D 복도에서 계단(`stairs3F`)을 누르거나 그냥 계단으로 내려가기만 해도(3층을 벗어나면) 연기 탈출이 시작됩니다. 불 앞까지 가지 않아도 됩니다. 소화기는 가는 길에 그대로 있습니다. 1층 신고 카드는 그때의 불 크기를 받습니다.
  - 엘리베이터 교정 대사는 3층에서만(`LookFirstScene.OnThird`, 서연은 303호 앞에 있음). 1층 엘리베이터는 원작처럼 `fire_lift` 토스트입니다. 살피기를 하지 않은 판의 연기 탈출도 원작 토스트입니다. 청각 모드에서는 서연이 뛰어나와 팔을 잡고 계단을 가리킵니다(외치지 않음).
  - '버티기'·'칸막이'도 화재 판단으로 칩니다: deed `fire_handled`가 `fire_waited`도 받습니다(원작 표에 없는 이벤트라 원작 대조에는 영향 없음). 304호 어르신이 두드리지 않은 판은 기다리기 전에 집 안(또는 베란다)에서 "불이야!" 외칠지 고르며, 외치면 원작 이벤트 `fire_shout`(`from: stay|partition`)가 남아 deed `fire_warned`와 도전 과제 "불 앞의 판단"에 닿을 수 있습니다.
  - 119 카드의 '무엇이 타는지'는 본 것만 말합니다(원인 없음): 작은 불 "304호 앞 복도의 택배 상자 더미가 타고 있어요.", 큰 불 "…불길이 천장까지 닿았어요."(`fire_report`의 "불의 규모와 상황"). '순서대로'·'가장 먼저'는 채점하지 않으므로 뺐습니다.
  - 칸막이 문구는 사실 문장대로 "발로 차서 부순다"(휠체어 모드 "힘껏 쳐서 부순다"). 칸막이를 부순 판은 그 뒤(5장 `ApplyHome`)에도 `partition = broken`이고, 살펴보기 문구가 "관리사무소에서 다시 막아 주기로 했다"로 바뀝니다.
  - 1장 '집 안 대비' 목표에 "베란다 끝: 경량칸막이 앞 비우기 (선택)" 단계를 보입니다(끝내는 조건은 원작 세 가지 그대로). 3D 상자는 밝은 골판지 색에 옅게 빛나는 운송장 라벨을 붙였습니다.
  - "복도 화재"(재개 키 "fire")는 살피기를 건너뛰지 않습니다. "fire"는 본 게임의 체크포인트·재시도 키이고 교사용 모드의 화재 강의(`fire_look`)도 이 칸이라, 건너뛰면 재시도와 수업에서 살피기가 빠집니다. 대신 칸 설명을 "먼저 살핀 뒤 복도로 나가, 소화기로 끌지 물러날지 판단합니다."로 바꿔 두 칸의 초점을 나눴습니다.

**2단계 3D 소화기 (11-21)**

**3단계 「304호의 계단」 어르신 시점 (11-21)**
- 2장 하위 장면입니다(챕터 목록·체크포인트 키는 그대로). 자리: 대피소에서 명부를 쓰고 자리를 잡은 뒤(`DDay.ShelteredMark` 다음), CPR 앞. 카드 "그 시각, 304호"(선택 · 약 3분)에서 '어르신의 걸음으로' / '건너뛰기'를 고르며, 어느 쪽이든 한 판에 한 번만(이벤트 `elder_pov`, 건너뛰면 `played: false`). 본 게임을 길게 만들지 않도록 선택 장면으로 두었습니다. 정민이 경보 때 304호 어르신을 만나지 않은 판(`elderPick` 없음)은 제안하지 않습니다. 교사용 모드의 공습경보 장면은 이 장면 전에서 끝납니다. 이야기 `Story/ElderPovScene.cs`, 규칙 `Game/ElderPovLogic.cs`, 시임 `DDay.ElderPart`(원작 대조 `DDayPlaythroughTests`·`DDayGoldenTests`는 CprPart와 함께 끄고 돌립니다).

- 같은 문장: 304호 앞의 대화는 원작 딜레마(`Elder.Ask`)의 어르신 대사를 글자 그대로 쓰고, 정민의 답은 그 판의 선택(help / manager / go)을 말로 옮긴 것입니다. 1층의 "다 왔네. 여기서부터는 소장님이랑…"도 원작 `Arrive` 대사 그대로입니다.
- 앞선 선택의 결과: help → 정민이 문 앞에서부터 곁에(나란히, 어르신 왼쪽 0.6m — 어깨 너머 카메라에 둘 다 보이게; 정민에게 불빛이 있었으면 그 불빛). manager → 정민이 1층 관리사무소 창구에서 실제로 알린 판(`know.elderTold`, `Elder.ManagerLine`)만: 어르신이 기다리면 박 소장이 3층까지, 먼저 내려가면 2층 층계참에서 만남. 알리겠다고 하고 창구에 들르지 않은 판(`ElderPovSetup.Way` = "untold")은 기다리다(2분) 스스로 내려가 go처럼 이어지고, 박 소장은 1층에서 순찰 중에 만나며 "정민 씨한테 들었어요"는 나오지 않습니다(돌아보기: "알리겠다고 했지만, 관리사무소 창구에는 들르지 못했습니다"). go → "소장님은 내가 여기 있는 줄 모르실 거예요"로 스스로 나서 2층까지 혼자, 2층에서 203호 이웃(휴대폰 불빛), 1층에서 순찰하던 박 소장. 「22분」 아침에 304호를 두드린 판은 그 뒤로 현관에 신발·작은 가방(약봉지·신분증·물)·손전등을 두어 손전등을 켜고 바로 나섭니다(아니면 '약봉지·신분증·휴대폰만' / '장롱 속 사진첩과 보따리까지(시간·무게)' — 중요서류는 늦어지는 쪽에 두지 않습니다, `docs_take`). 정전 때 촛불 당부(`elder_candle_tip`)를 한 판은 촛불부터 끄고, 아니면 끌지 고릅니다. 켜 둔 채면 문 앞에서 함께 나서는 사람(정민 / 기다린 박 소장)이 "촛불은 끄고 가요"라고 해서 끄고(`reminded`), 혼자 나섰으면 켜 둔 채 1층에서 박 소장이 "지금은 다시 올라가지 말고 대피부터, 경보가 풀리면 304호부터 가 볼게요"라고 하고 `candle_rules`를 보여 줍니다(정민 자신의 촛불과 같이 공습경보 중 다시 올라가는 사람은 없음, 처벌 없음). 2장 계단에서 무거운 배낭(`bag_heavy` stairs)을 멘 정민은 어르신의 눈에 "그래도 내 팔을 놓지 않네요"로 남습니다. 1장 인사(`elder_met`)는 "문을 두드려 달라고 했지요" 한 줄.

- 쉬운 한국어(`Game/EasyKorean.cs`): 원문을 고치지 않고 보여 줄 때만 바꿉니다. 이야기·저장·테스트는 원문 그대로이므로 원작 대조 테스트에 영향이 없습니다. 바꾸는 자리: `StoryOverlay`(대화 줄·선택지, 카드 제목·본문·버튼, 토스트, 자막, 목표와 단계, 시간 건너뛰기), `UiKit.Label`(코드로 만든 모든 화면의 처음 글자), 미니게임 화면의 사실 줄(`CprScreen`·`LookFirstScreen`·`SightingScreen`·`BreatheScreen`·`ExtGaugeScreen`·`ExtinguisherScreen`), 퀴즈 읽어 주기. 문장 지도 `EasyKorean.Map`(약 80줄: 프롤로그 분류 튜토리얼과 조작 카드, HUD 목표, 대피소·화재 안내 대사, CPR·살펴서 대피·소화기·숨 고르기 안내, 교사용 모드 소개와 장면 바로가기 설명, 퀴즈 질문). 퀴즈 보기는 바꾸지 않았습니다(정답·오답의 길이와 차이가 문항 설계의 일부). 설정을 바꾸면 화면의 목표는 바로 다시 그려지고, 나머지는 다음에 뜨는 글부터 바뀝니다.
- 사실의 쉬운 말: `facts-ext.json`의 맨 위 `plain` 지도(사실 id → 쉬운 문장, 69개: 원작 facts.json 40개 + 확장 29개, 설명 `plainNote`). facts.json은 건드리지 않았고, 확장 사실의 모양(`id, topic, sourceId, text`)도 그대로입니다. `Facts.Plain(id)`·`PlainTexts`, `Facts.Merge`가 병합본에 붙이고, `GameSession`이 `EasyKorean.UseFacts`로 사실 문장 → 쉬운 문장을 찾게 합니다(교사용 모드 수업 카드, 생존 가이드, 엔딩 문서 등 사실 문장이 그대로 보이는 곳은 자동으로 바뀜). 쉬운 문장은 출처와 대조해 확인한 원문(같은 id)을 기준으로 뜻·조건·숫자·전화번호를 그대로 두고 한자어를 바꾸거나 문장을 나눈 것입니다(새 사실 없음). 괄호 설명은 다른 확인된 사실에서만 가져왔습니다(경량칸막이 `fire_partition`, 하향식 피난구 `home_hatch`). 이 작업에서 출처 페이지를 다시 열지는 않았습니다.
- 규칙(테스트): 쉬운 문장은 원문과 달라야 하고, 원문의 숫자를 모두 담고(약 5cm, 100~120, 30:2, 112·119·1338…), 어려운 말 목록(`EasyKorean.HardWords`: 즉시, 신속, 지체 없이, 명부, 소등, 자제, 착용…)을 쓰지 않고, 한 문장이 64자 이하입니다. 사실 쉬운 문장에도 2분 교대·1337·111·113·욕실·칸막이 수치가 없고, 외국·보조 자료 표시((미국 …), (캐나다 …), (식약처))를 그대로 둡니다. 지도의 원문이 코드에서 사라지면(문구를 고치면) 테스트가 알려 줍니다.
- 도우미 모드(`Game/Companion.cs` 말, `UI/CompanionPanel.cs` 화면, 정렬 226): 같은 PC 옆 사람(부모·교사·심사위원)이 조작을 넘겨받지 않고 돕습니다. 왼쪽 아래 "도우미 F1 힌트" 칩(돌아다닐 때는 상태 패널 위, 화면이 열리면 구석), F1이나 칩을 누르면 힌트(열린 화면이 있으면 그 화면의 조작 요령, 없으면 지금 목표와 다음 할 일, 주제에 맞는 확인된 사실 한 줄과 발행처; 퀴즈 중에는 사실을 보이지 않음). 판단 순간에는 "함께 생각해 보기" 카드가 게임을 멈추고(Time.timeScale 0) "나라면 어떻게 할까요?"와 주제별 질문 두 개, 아직 고를 수 있는 것(이미 고른·잠긴 선택지는 빼고), 도우미에게 주는 말("답을 먼저 알려 주기보다, 무엇을 고르려는지와 그 이유를 들어 주세요")을 보여 줍니다. Enter·Space·패드 A·버튼으로 닫으면 선택지가 나옵니다. 자리: 화자 또는 역할이 "판단"인 대화(선택지 위, 화면 위쪽), decision 카드(4장 「지금 내 상황」; 화면 아래쪽. 304호 제안처럼 "건너뛰기"가 있거나 Meta가 "선택 ·"인 선택 장면 제안은 판단이 아니라 빼고, `Companion.CardDiscusses`). 화면 자체의 판단(`LookFirstScreen` "fire", `SightingScreen` "report")은 `DecisionMoment.Begin(topic)`의 새 `Began`/`Ended` 이벤트로 오른쪽 아래에 질문만 띄우고 멈추지 않습니다(화면이 키를 직접 읽어 막을 수 없음). 카드의 말은 열린 질문과 조작 요령뿐이고 숫자·안전 문장을 새로 만들지 않습니다(안전 문장은 사실 id). `UnityStoryHost.Open`이 열린 화면 이름을 `Companion.PushScreen/PopScreen`으로 알립니다.
- 문구 일관성: wave 1~3 문자열을 용어(경보·대피소·재난문자·행정복지센터·행동요령), 띄어쓰기, 겹친 조사, 맞춤법 패턴으로 훑었습니다. 고친 것: "행동 요령" 7곳 → "행동요령"(공식 표기, 사실·출처 이름과 같게: 생존 가이드 제목, 조작 안내 K, 리포트 준수율, 퀴즈 안내 등), 서술문의 "주민센터" 2곳 → "행정복지센터"(`Endings` cpr_relay 문장, `RumorAnatomy` 배식 시간 해부; 사람의 말 속 "주민센터"는 그대로). 재난문자(띄어 쓴 곳 없음), 경계경보·공습경보, 경보해제, 경량칸막이, 1338 표기는 이미 한결같았습니다. "단체방"은 원작 5장 지름길 소문의 출처 이름이라 그대로 둡니다.
- 테스트: `EasyKoreanTests`(지도의 원문이 코드에 있음, 쉬운 문장 규칙, 규칙이 숫자 누락·어려운 말·긴 문장을 잡음, 사실 쉬운 문장의 id·뜻 표지(약 5cm·100~120, 30:2·가슴 누르기만 계속, 사이렌 없이·1분, 1338·경찰서, 문 닫고 젖은 수건·119), facts.json 무변경, 수업 카드·힌트·퀴즈 사실의 쉬운 문장, 꺼짐/켜짐, 줄 단위·"제목 — 사실" 찾기, 대화·카드·단계 사본과 id 유지, 설정 폼, 디렉터가 켜고 끔), `CompanionTests`(주제, 판단 카드 질문, 말에 숫자·어려운 말 없음, 힌트 사실이 확인된 사실, 목표와 다음 할 일, 고를 수 있는 것, 열린 화면 우선·퀴즈에는 사실 없음, 할 일 없음). 준비된 저장은 이야기 상태를 바꾸지 않아 다시 만들지 않았습니다.
- 리뷰 반영(11-21): (1) 판단 카드는 판단 하나에 한 번입니다(`Companion.FirstPass`: 지금 고를 수 있는 선택지의 절반 이상이 바로 앞 카드에 있었으면 같은 판단을 다시 묻는 것으로 보고 건너뜀). 5장 연기 질문을 문손잡이 뒤에 다시 물을 때와 「22분」의 "그다음은?"은 카드 없이 선택지로 갑니다(「22분」 한 판에 카드 1장, 테스트). 마지막 돌아보기 "다음에 또 경보 문자가 오면?"은 새 판단이라 카드가 뜨고 주제 `reflect`("이번에 잘한 것과 아쉬운 것은?", "다음에는 무엇부터 확인할까요?")를 씁니다. (2) 칩과 F1은 이야기가 진행 중일 때만(`Companion.RunActive`, `RunChapters`가 켬) 보이고, 타이틀(`TitleOnce` 처음)과 `TitleReturn.ToTitle`이 `Companion.Reset()`으로 지난 판의 목표·화면·카드를 잊습니다. (3) 화면 위의 힌트 판은 그 화면 창 옆의 넓은 여백(300px 이상)에 위에서부터 놓입니다(`UiScreen.TopWindow`); 여백이 없으면 구석 칩 위에 좁게. 라디오 조작 요령은 화면의 "힌트 보기" 버튼을 가리킵니다. (4) 경보 질문은 경로를 가리지 않게("지금 받은 경보는 어떤 경보일까요? 사이렌·방송·문자 가운데 무엇으로 알았나요?") 바꿨습니다(경계경보는 사이렌이 없고, 청각 모드). (5) 쉬운 말에서 공식 이름은 바꾸지 않고 처음 나올 때 괄호로 풉니다: "임시 거처(잠시 지내는 곳)", "명부(이름 적는 종이)", "행정복지센터(주민센터)". 어려운 말 규칙은 바로 뒤에 괄호 설명이 붙은 경우를 허용합니다. 쉬운 문장이 원문의 이름(임시 거처, 명부, 행정복지센터, 대피소, 경량칸막이, 하향식 피난구, 대피공간)을 빠뜨리지 않는지 테스트합니다. (6) 사실 쉬운 문장 두 개를 원문 뜻에 맞췄습니다: `alert_caution` "먼저 대피" → "미리 대피"(사전 대피), `suspect_report` "관공서에" → "관공서 등에". `fire_own_trapped`의 쉬운 문장은 UI와 `home_hatch`처럼 "하향식 피난구"로 띄어 씁니다(원문 사실 문장은 그대로). `plainNote`의 설정 위치를 실제 자리로 고쳤습니다.
- 표기 규칙(리뷰 반영): 서술·UI는 "행정복지센터", 사람의 말(따옴표 안의 대사, "— 303호" 같은 쪽지 글)은 입말 "주민센터"를 그대로 둡니다(5장 결정 카드의 서연 대사, `Rumors` 303호 쪽지). "경보 문자"는 고치지 않았습니다: 원작 확인 사실(`facts.json`의 "경보 문자는 시각, 원인, 지역…", 출처 이름 "민방위 경보 문자 표준 문안")이 쓰는 말이고, 재난문자 가운데 경보를 알리는 문자를 가리키는 좁은 말이라 "재난문자"로 바꾸면 뜻이 넓어집니다. wave 3 사실 `home_exits_know`의 "대피 공간 … 경량 칸막이" 띄어쓰기는 출처(소방청 보도자료 2022.10.6) 본문이 첨부 hwp에만 있어 이번에 대조하지 못해 그대로 두었습니다(뜻은 같음, 다음 사실 점검 때 확인).
